SESSION 2 — restructured into one continuous 30s shot.

WHY
Review feedback: the two cut scenes were the right *style* but the wrong
*structure* — 33 seconds that covered only "someone typed" and "words become
chips", with a hard cut between them. What the video wants to be is a factory
tour: one camera move through a set that is built once, close on each machine,
then a pull-back showing the whole plant running end to end.

BUILT
- lib/camera.py — focus / frame_all / snap_to. Returns built Animations so a
  camera move can be played *with* the action at its destination; that is what
  makes the shot feel continuous instead of stop-and-go.
- lib/components/factory.py — Station, PipelineBox, Conveyor, rail_between.
  Reusable well beyond LLMs: any "how X works" explainer is a factory tour.
- lib/components/chat_ui.StreamingBubble — text arriving a word at a time.
- scenes/factory_set.py — the set: chat, web server, four stations inside one
  model box, and a return rail closing the loop. ~48 units wide, so the final
  pull-back is 3.3x.
- scenes/scene_factory.py — the choreography, 8 beats, 29.3s.
- Deleted scene_01_user_input.py and scene_03_tokenization.py. Both beats live
  on inside the factory shot; keeping them would have been dead code.

WHAT WENT WRONG (and what the fix was)
- Tight shots clipped their subject. W_TIGHT was 8.4, which at 16:9 is only 4.7
  of frame height — a 5.2-tall station bay does not fit, let alone its caption.
  Raised to 12.0. Found by looking at frames; no test could have caught it, and
  the reason is now a comment next to the constant.
- Station marquees overlapped each other and the "THE MODEL" title in the wide
  shot. Fixed by clamping each marquee to its bay width and moving it below the
  bay. Two tests now guard both properties.
- The PipelineBox title hung down into every station close-up. Its `pad` is what
  lifts it clear, so pad went 1.1 → 2.2 and the docstring now says that is what
  pad is for.
- The "prediction" vector escaped the transformer bay, because it was positioned
  next_to the stack *after* the stack had been fitted. Now the stack and the
  output are grouped and fitted together.
- StreamingBubble v1 built one Text per word and arranged them. arrange centres
  on the bounding box, so "your" floated visibly above its neighbours. Rebuilt
  on a single Text with explicit line breaks, addressing words by glyph range.
  Two regression tests: common baseline, and descenders still dipping.
- The greedy word wrap measured words in isolation, so kerning across a space
  could push a line 0.005 over max_width. Clamped after construction.
- Camera focus on a Station now targets `station.bay`, not the station group —
  the group includes the invisible marquee hanging below it, which dragged the
  framing down.

KNOWN GAPS (not bugs)
- No voice-over, so pacing is eyeballed against the script's beat sheet rather
  than locked to narration. Tracked as `voiceover-pass`.
- The transformer close-up sweeps the stack but does not show attention links,
  even though AttentionLines and AttentionMatrix exist and are tested. It was a
  4-second beat and adding attention made it feel rushed. Tracked as
  `attention-detail` — needs a call on whether the beat gets longer or the
  video gets longer.
- In the final wide shot the reply text is too small to read. That is inherent
  to a 3.3x pull-back and was accepted: the beat is about seeing the circuit,
  not the words. If it should read, the chat window needs to be bigger in world
  space, which changes every earlier shot.

NEXT
- Highest-priority incomplete item is `voiceover-pass`.
- If more length is wanted, `attention-detail` is the best next beat: the
  components already exist and are tested, so it is choreography only.


================================================================================
SESSION 7 - the ending review: overflow, blob icons, and a starved slot
================================================================================

Asked to review the finished cut and fix what looked wrong. Three complaints,
all of them real, all of them visible only in a frame:

1. "boxes overlapping the text"
   The reply bubble was built by the scene and positioned by hand relative to
   the last message. The window never saw it, so nothing checked it fit: a
   four-line reply in a 3.8-tall window hung out of the bottom of the frame,
   across the composer and over the web server below it.

2. "small half boxes near before the text"
   Same bug, seen from the other side. The half box was the COMPOSER, sticking
   out from behind the overflowing reply. Nothing was drawing a stray
   rectangle; a box that should have been in front was behind.

3. "the embed token texts are too large ... the content inside them being big"
   Exactly right, and the cause was a decision recorded in session 5. Bay
   titles were sized for SHOT_LABEL=26 so that ONE label would read both in the
   close-up and at the pull-back. At the close-up (13.6) that is roughly double
   size: title plus subtitle took 58% of a 9.6-wide bay and the slot - where
   the chips, the vectors and the chart go - got 2.5 units. Five vector columns
   in 2.5 units is confetti.

WHAT CHANGED

- The chat window now places the reply. `ChatWindow.place`/`post` flow an
  externally built bubble through the same path `add_message` uses, so it lands
  in the gutters and gets the existing scroll-and-clear-the-composer handling.
  `message_area_height` says how much room a bubble actually has, and the scene
  shrinks the reply to it rather than hoping.
- The window grew to 9.6 x 7.0 - the width of a bay, so it reads as the top of
  the same column - which is what lets BOTH messages stay visible at the end
  instead of the question scrolling away. W_CHAT went to 14.0, the frame width
  lib/components/chat_ui is actually drawn for.
- Two labels per bay again, but as a real cross-fade this time. The close-up
  header is sized for SHOT_TIGHT and the pull-back gets `wide_label` sized for
  SHOT_WIDE, and `reveal_labels()` swaps them. This is the thing session 5
  recorded as "tried and removed" - it failed then because both were lit at
  once and the swap fought an `arrive`/`settle` scale on the same group. The
  scaling is gone, and only one label is ever visible.
- HEADER_SHARE 0.58 -> 0.36. The slot went 2.5 -> 4.6 units and the vectors are
  now readable at the close-up.
- The server -> model rail no longer draws a line through the middle of "THE
  MODEL": it stops above the caption, and `routing.join` bridges the gap, so
  the travelling token still crosses it. Its other end starts below the
  server's own caption rather than behind it.
- Pull-back comet dissipation 0.14 -> 0.08s. At circuit speed the longer tail
  reached from the transformer to the corner and its per-frame chords cut
  visibly across the bays.
- SHOT_WIDE 48.5 -> 57.8, which is what the taller stack actually needs.
  `validate()` catches this, which is the only reason it is right.

THE ONE THAT WOULD HAVE SHIPPED
Bringing the wide labels up turned every bay icon into a solid white blob. A
Lucide icon is a stroked outline with the fill deliberately cleared, and
`set_opacity` raises FILL opacity too. FadeIn gets away with it because it
interpolates back to the authored state; an absolute `set_opacity(1.0)` does
not. This is the same class of bug as session 5's glow halos - the fix there
was "animate stroke, not fill", and it is the fix here: `Glyph.fade_to_opacity`
fades outlines on stroke and indicator dots on fill, and `Station._fade_parts`
routes each half of a label to the channel it uses.

Nothing in the model was wrong at any point. All three bugs were compositing,
and all three were invisible to the snapshot grid. Frames, every time.
