Newest entry last. One entry per session: what was built, what was tried that

SESSION 1 — setup phase. Harness + /lib + first two scenes.

BUILT
- Environment: python 3.11 venv, manim 0.21.0, ffmpeg 6.1, cairo/pango system
  deps. init.sh reproduces this from cold and is idempotent.
- Repo installed editable (pyproject.toml) so scenes can `from lib import ...`
  under `manim render` without sys.path hacks at the top of every file.
- lib/theme.py, lib/utils.py, lib/transitions.py.
- lib/components/: chat_ui, tokens, vectors, network, probability, transformer.
- tests/: 54 structural tests + 10 snapshot cases with approved baselines.
- scripts/evaluate.py (the Evaluator: lint, import, unit, snapshot, render),
  scripts/approve_baselines.py, scripts/new_video.py.
- .claude/hooks/guard_protected_paths.py + .claude/settings.json.
- videos/chatgpt_message_journey/ with script.md (all 8 scenes), feature_list,
  scenes.json, render.py, and scenes 1 (UserInput) and 3 (Tokenization) built.
- Evaluator green on all five gates; render.py cuts a 33s draft of both scenes.

WHAT WENT WRONG (and what the fix was)
- `utils.is_in_frame` had an inverted comparison on the top edge — every
  component "overflowed". Caught by the first structural test run, not by eye.
  Lesson: the in_frame fixture earns its keep.
- `VectorColumn.dim` and `ProbabilityBar.dim` both collided with attributes
  Manim's Mobject already owns. `dim` is a property with no setter on Mobject,
  so construction failed outright; the probability one failed at call time.
  Renamed to `dimension` / `deemphasise`. Recorded in docs/component-guide.md.
- VectorColumn's truncation was off by one — 7 rows for truncate_at=6.
- ChatWindow bubbles overlapped the composer, and scrolled-off bubbles drew over
  the title bar. Added a bottom clamp plus opacity-based clipping
  (`visible_messages`). Found by LOOKING at the render, not by the tests.
- AttentionMatrix column labels collided at small cell sizes. Added
  `rotate_col_labels` to EmbeddingGrid.
- `window.input.animate.clear()` raised "zip() argument 2 is longer than
  argument 1" — `.animate` cannot interpolate across a structural change.
  Composer reset is now a hard cut, which is also what a real composer does.
- Scene 3's split-word callout braced chips across two rows and looked wrong.
  Switched the strip to a single row.

BLOCKED — NEEDS A HUMAN
1. The protected-path hook's Bash matcher is too broad. It blocks any command
   that both mentions a protected path and contains a redirect, so
   `python scripts/evaluate.py 2>&1 | tail` and heredocs that merely *document*
   the Evaluator are refused. The hook protects `.claude/hooks/`, i.e. itself,
   so an agent session cannot fix it — that is the bootstrap flaw, and it is
   deliberate that I did not route around it. Fix is written up as
   feature `harness-hook-bash-false-positive`. Workaround meanwhile: use the
   Write tool for such files, and avoid `>` redirects in commands that name a
   protected path.
2. No CI yet — `.github/workflows/` is protected for the same reason, so the
   workflow has to be added by a human. Tracked as `harness-ci`. Until then the
   Evaluator is a local gate only.

KNOWN GAPS (not bugs)
- Rendered scene lengths (10s and 18s) are well short of their script budgets
  (45s and 55s). Expected: the budgets assume narration. Timing gets locked in a
  voice-over pass; do not pad with empty waits.
- Snapshot signatures cannot see small colour shifts or single-glyph typos.
  Stated in AGENTS.md so nobody reports those as verified.

NEXT SESSION

  videos/chatgpt_message_journey/feature_list.json. All its /lib components
  (network.RequestPath, PacketStream, ServerRack) already exist and are tested,
  so it should be assembly rather than new component work.
- Add the scene to scenes.json only once it renders green.

SESSION 3 — the look becomes the standard. Motion language + icons + a skill.

WHY
Review feedback: the continuous shot works, but the components were plain boxes
and the motion lacked the polish of ByteByteGo-style explainers. Researched what
they use (After Effects — so a hand-keyframed pipeline, not a rival code tool)
and probed what Manim can actually do before promising anything.

WHAT THE PROBE ESTABLISHED (kept because it stops the question being re-asked)
- Vector icons: yes. SVGMobject imports Lucide cleanly.
- Glow: no native blur, but concentric stroked copies look right.
- Gradients, 55 easing curves, TracedPath comet trails: all present in 0.21.
- Motion blur: not in Manim; an ffmpeg tmix frame-blend pass costs about the
  clip's own duration and is now wired into the render profiles.
- True gaussian blur / soft drop shadow behind a filled card: still not possible
  without post-processing. This is the one real gap.
- Benchmarked at 1080p60: a 12-layer stroke glow renders in ~1.4s per
  animation-second; an equivalent pre-blurred ImageMobject sprite takes ~5.6s.
  This is the OPPOSITE of what I assumed going in — Cairo's alpha compositing is
  the bottleneck, not path count, and layer count barely matters. Layered strokes
  are both the better-looking and the cheaper option.

BUILT
- lib/motion.py — the motion language. Real cubic-Beziers of the Material curves
  (not approximations of Manim's named rate functions), semantic aliases
  ENTER/EXIT/MOVE/SNAP/FEATURE, duration tokens, sub-linear distance scaling,
  staggered entrance helper.
- lib/effects.py — glow, Glowing, comet, pulse.
- lib/components/glyph.py + lib/assets/icons/ — 24 vendored Lucide icons (ISC),
  Glyph and IconTile.
- Station gained an icon slot; the factory set now uses icons and pre-built glow
  halos, and every play() in the scene carries a named easing curve.
- Motion blur wired into harness.json + render.py, and scripts/new_video.py now
  scaffolds a render.py byte-identical to the live one (verified by diff).
- .claude/skills/factory-video/ — the house format written down, with a
  reference file recording the motion standards' sources and Manim's real limits.
- 54 more tests (143 total) and 4 more baselines (19 total).

WHAT WENT WRONG
- Syncing render.py into the scaffold template needed brace escaping AND
  backslash escaping, in that order. Got it wrong twice; the fix is verified by
  diffing a freshly scaffolded render.py against the live one, which is now the
  standing check.
- A glow test asserted the halo's bounding box exceeds its source. It does not:
  Manim's .width is path geometry and ignores stroke entirely, so the halo shares
  the source's box and the light spills out through stroke width alone. The test
  was wrong, not the code.
- The end-loop comet had a 0.5s dissipation, which at that speed drew a hard
  orange line straight through the machines instead of a trail. 0.14s reads as a
  comet. Found by looking at frames, as usual.
- Lucide draws indicator dots as zero-length lines with round caps, which Manim
  renders as nothing — the server icon silently lost both status lights. Glyph
  now detects degenerate sub-paths and substitutes real dots. There is a test.

STILL BLOCKED ON A HUMAN (unchanged)
1. harness-hook-bash-false-positive — the protected-path hook still blocks any
   Bash command that mentions a protected path alongside a redirect, and it
   protects itself so no agent session can fix it. Cost time again this session.
2. harness-ci — no CI, same self-protection reason.

NEXT

- attention-detail beat, if the video is allowed to grow.

SESSION 4 — vertical column layout, type system, routing guarantees.

WHY
Review of the previous cut: (1) the motion blur made everything feel like slow
motion and shaky, especially on the pull-back; (2) the end-loop trail cut
straight through the boxes instead of following the drawn rails; (3) the
typography at the wide shot looked wrong; (4) the loop was spread too far.

BUILT
- lib/typography.py — type as a share of FRAME HEIGHT, with the point size
  derived from the shot it is read in. Measured calibration: Manim's cap height
  is linear at 0.010128 world units per point, pinned by a test so a Manim
  upgrade cannot silently rescale the back catalogue. This is the real fix for
  "typography looks odd": the old code had arbitrary x2.6 / x1.8 / x2.2
  multipliers and label sizes ranged from 1.8% to 3.5% of frame height with no
  system behind them.
- lib/routing.py — elbow(), join(), and the clearance predicates. The travel
  path is now BUILT FROM the drawn rails, so it cannot disagree with them, and
  the set asserts its own geometry at construction.
- Station gained header_side ("top"/"left") and marquee_side/role/max-width;
  PipelineBox's title moved outside its frame.
- Motion blur is now OFF on every profile, with the reasoning recorded in
  harness.json next to the setting.
- Layout rebuilt as a single vertical column per the brief: chat on top, server,
  then the model box with tokenize/embed/attend/sample stacked, and the token
  climbing back up the right-hand side.

MEASUREMENTS WORTH KEEPING
- Old horizontal layout: 3.59x pull-back. A compact 2x2 circuit reached 1.98x.
  The vertical column asked for is height-bound at 16:9 and lands at 3.24x.
  That trade was made knowingly and stated to the user with the numbers; it is
  survivable only because type is now shot-relative.
- A tall column leaves the sides of a 16:9 frame empty, so station marquees moved
  to the LEFT of their bays — it fills otherwise-wasted margin and keeps the
  stack short.

WHAT WENT WRONG
- The trail bug was NOT what it looked like. The circuit path was clean; the
  cause was attaching the comet to a Dot *before* placing it on the path.
  TracedPath traces get_center from the frame it is added, so the dot's first
  traced point was wherever it happened to sit (the origin), producing one long
  chord across the whole set that looked exactly like a routing failure. Both
  trails now get positioned first. This is in the skill.
- path_clears walks the true curve and therefore cannot see corner-cutting by a
  trail's per-frame chords. Added chord_violations/assert_trail_clears, which
  models what TracedPath actually draws, and the set asserts it at 30 frames.
- Positioned stations with `st.bay.move_to(...)` then shifted the group, which
  moved the bay INSIDE its own group and detached it from its header and
  marquee. Rendered as garbled overlapping labels. One shift of the whole group
  is correct; there is now a comment at both call sites.
- The self-imposed zoom cap in validate() fired when the box title moved
  outside the frame and grew the set. That is the guard working — the fix was to
  make the set genuinely more compact, not to raise the cap.
- Three of my own new tests were wrong rather than the code: a glow bbox
  assertion (Manim's .width ignores stroke), a share-consistency tolerance
  tighter than rasteriser rounding, and a readability check measured on a
  lowercase-only string whose box is far shorter than its role's cap height.

STILL BLOCKED ON A HUMAN (unchanged, fourth session)
1. harness-hook-bash-false-positive — the protected-path hook blocks any Bash
   command mentioning a protected path alongside a redirect, and it protects
   itself, so no agent session can fix it.
2. harness-ci — no CI, same self-protection reason.
